# 医院资源与经营总览看板设计

## 目标

让后台运营人员在一个页面回答三类问题：当前医院资源规模如何、口腔/整形医院分布如何、不同类型医院实际产生了多少业务。所有汇总数字都必须能通过筛选和下钻解释。

## 一期范围

首屏提供医院总数、整形医院数、口腔医院数、未分类医院数和当前周期新增医院数，并展示分类占比。分布区域默认按省份聚合，支持下钻到城市和医院明细。明细至少包含医院、类型、省市、启用状态、派单数、到院数、成交数和最近派单时间。

顶部筛选统一作用于全部内容：时间范围、医院类型、省份、城市和医院状态。默认时间范围为当前累计数据；选择时间范围后，新增医院和业务指标按该范围统计。页面显示当前统计口径和生成时间。

二期在同一数据模型上增加按医院类型的派单量、客户数、已联系数、到院数、成交数、到院率和成交率对比，以及趋势和医院排名。本次不实现复杂预测或 AI 分析。

## 数据口径

- 医院数量按 `crm_hospital` 去重，软删除医院排除。
- 类型以 `crm_hospital.category` 为准；`oral` 为口腔，`plastic` 为整形，空值或未知值归入未分类。
- 业务指标基于派单记录统计，不以医院数量推算。
- 到院率和成交率的分母固定为当前筛选范围内的派单数；分母为零时返回 0。
- 所有聚合结果必须携带筛选条件和 `generatedAt`，前端不得拼接不同请求的口径。
- 医院明细使用分页查询；汇总接口不返回全量医院记录。

## 页面结构

1. 筛选栏：时间、医院类型、省份、城市、医院状态、刷新。
2. KPI 区：五张指标卡，显示数值、占比或环比，并提供“查看明细”入口。
3. 分类构成：口腔、整形、未分类的数量和比例，未分类提供治理入口。
4. 分布区：省份/城市分组柱状图与可切换明细表；点击省份下钻城市，点击城市打开医院明细。
5. 业务表现区：口腔与整形的业务指标对比，预留二期接口字段。

## 交互方案

页面顶部固定显示当前分析上下文（医院范围、类型、时间和状态），筛选会联动所有模块，并同步到 URL。KPI 卡片可点击并转化为全局筛选，而不是打开孤立弹窗。

分布区默认按省份显示横向排名和分组条形图，支持切换城市/类型；不把地图作为默认视图。点击省份后使用右侧抽屉下钻到城市，再下钻到医院明细，抽屉继承主页面筛选条件。未分类医院作为数据治理任务突出展示，支持进入明细并批量补齐类型。

所有汇总数字提供“查看明细”入口和口径说明；刷新、导出和生成时间属于同一分析上下文。空态、错误态和加载态分别处理，加载期间保留上一次数据。

## 后端接口

新增聚合接口：

```text
GET /api/crm/v1/dashboard/hospital-overview
```

请求参数：`startDate`、`endDate`、`category`、`provinceCode`、`cityCode`、`status`。

响应分为 `summary`、`byCategory`、`byProvince`、`byCity`、`businessByCategory`、`generatedAt`。一期可以让 `businessByCategory` 返回空或基础字段，但字段结构保持稳定，二期补齐业务指标。医院明细沿用现有分页医院查询，并增加可选的聚合筛选参数。

服务层继续执行角色数据范围校验：超级管理员可查看全量并筛选，普通后台角色只能查看已有授权范围；医院账号不暴露该后台总览接口。

## 性能与一致性

汇总查询按聚合维度一次完成，避免按省份或类型循环请求。对医院类型、状态和创建时间建立组合索引评估；大数据量下按查询计划决定是否增加汇总表。前端请求序列号防止旧筛选响应覆盖新筛选，加载失败保留上一次数据并显示重试。

## 测试与验收

- 服务层测试类型映射、未分类、软删除、时间边界和权限范围。
- 仓储层测试省份/城市/类型聚合以及零数据返回。
- 前端测试筛选联动、下钻、空态、错误态和数字格式化。
- 验收时验证：分类总数等于明细去重总数；省份合计等于总数；未分类可定位到具体医院；任一 KPI 可打开对应明细。

## 非目标

本期不修改医院账号权限，不引入实时数仓，不实现地图热力图、预测模型或复杂自定义报表。
