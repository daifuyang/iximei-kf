### 3.1 关于 spec §4.2 与现有 setInitialState 架构冲突的 disclose

**事实**（T1 review 独立复核确认）：

1. spec §4.1 贴出的「当前组件」代码是 `const [count, setCount] = useState(0)` + 渲染 `<Badge>`，**与 `git show d487cfb:` 的真实文件不符** —— 实际是 `return null` + `useModel('@@initialState')` + `setInitialState({ dispatchUnviewedCount })`。
2. spec §4.2 示例代码完全抛弃 `useModel` / `setInitialState` 桥接，改用纯本地 `useState` + `useRef`，会切断 `apps/yishan-admin/src/app.tsx:258-285` 的 `menuItemRender` 数据来源（`menuItemRender` 直接读 `initialState.dispatchUnviewedCount`）。
3. spec §4.2 用 `res?.success` 门控；现有实现用 `Number(res?.data?.count ?? 0) || 0`（silent-resilient 兼容「成功但 success 缺失」/「data 直接是 count」两种老契约）。

**T1 implementer 的处理**（严格按 brief §1.1「不照搬」约定）：
- **保留** `useModel('@@initialState')` + `setInitialState` 桥接机制（Phase B T10 已上的功能，破坏它会回退 1 个 phase）。
- **新增** 4 个 spec §4.2 要求的 hook：`useDocumentTitle` / `useNotificationPermission` / `useBrowserNotification` / `useVisibilityRefresh`，且在所有 `return null` **之前**注册（避免 React hooks 顺序漂移）。
- **新增** 本地 `useState` + `useRef` 跟踪 `count` / `lastCount` / `loading` —— 作为 4 个 hook 的本地数据源。
- **保留** `return null`（不抢布局空间，badge 渲染仍归 `app.tsx:menuItemRender`）。
- **保留** 现有 silent `console.warn` 失败处理 + `ROLE_IDS.HOSPITAL_ACCOUNT` enum 引用（Phase B T10 fix）。
- **保留** `Number(res?.data?.count ?? 0) || 0` 的 silent-resilient 解析（不引入 `success` 门控以避免破坏老契约）。

**Reviewer 判定**：spec §4.1/§4.2 是 spec 撰写时的缺陷（未 read 现有代码），而非 implementation 偏离。Spec §1 的能力目标与 §4.3/§5 的行为验收是真正的判据，spec §4.2 是 illustrative 代码，其错误前提不能反过来要求实现去复现一个会破坏 Phase B T10 的结构。**Spec compliance: ✅ PASS, Task quality: ✅ Approved**。

**给 T3 提个醒**：
- 组件 `return null` —— badge 由 `apps/yishan-admin/src/app.tsx:menuItemRender` 渲染；不要到组件里找 `<Badge>` JSX，否则会找不到。
- 4 个 hook 都已挂载但 `dot` loading 的 UI 端未生效 —— T1 单文件约束下无法跨文件改 `app.tsx` 加 `dot` prop；如要补全需另立 task 改 `menuItemRender`（详见 §6 Follow-up F2）。

## 6. Follow-up（建议后续 ticket，不阻塞）

1. **Finding 1 — stale closure `lastCountRef.current = count`**：T1 `fetchCount` 用 `useCallback([enabled, setInitialState])`，闭包里 `count` 永远是首次渲染的 `0` → `useBrowserNotification` 判据退化为 `count > 0` → 过度触发（重复触发而非漏报，tag 去重后用户感知骚扰有限）。**修法 1 行**：在 `fetchCount` 里改用函数式 `setCount(prev => { lastCountRef.current = prev; return next; })`。建议 T3 顺手修。
2. **Finding 2 — dot loading 数据/UI 两端未串联**：(i) `setLoading(true)` 只更新本地 state，没同步写 `initialState.dispatchUnviewedLoading: true`（成功 / finally 分支都写 `false`）→ 全局字段恒为 `false`；(ii) `app.tsx:menuItemRender` 根本没读 `dispatchUnviewedLoading`，也没 `dot` prop → dot loading 功能上是 dead code。建议另立 task：(a) 删 dot loading（spec §1 A.5 降级为「仅 99+ 截断」），或 (b) 跨 2 文件补全（需突破 T1 单文件约束）。
3. **Finding 3 — `ORIGIN_TITLE` 模块加载期求值 pin 住旧标题**：与 spec §4.2 示例逐字相同，非 implementer 缺陷；spec 后续修订参考（真要修改为 `useRef` 惰性捕获当前标题）。
4. **spec §4.1/§4.2 应更新**（建议下个 spec cycle 修订）：
   - §4.1 替换为 d487cfb 的真实组件代码
   - §4.2 示例改为「保留 setInitialState 桥接 + 追加 4 hook + 保持 `return null`」
   - §4.2 删除 `import { Statistic } from 'antd'`（未使用）
   - §1 A.5「数字动画（antd CountUp 或 Statistic）」实际未实现动画，只实现 99+ 截断 —— 需澄清或降级
